# PlutosOil — Реестр покупателей (отдельный сайт)

Готовый проект: React + Supabase (общая база, синхронизация в реальном времени) + Vercel (хостинг).
Ниже — всё по шагам, без предположений, что вы уже это делали.

## Шаг 1. Supabase (база данных, бесплатно)

1. Зайдите на **supabase.com** → Sign up → создайте проект (Name: `plutosoil`, пароль базы задайте любой, регион — ближайший, например Frankfurt).
2. Подождите 1–2 минуты, пока проект поднимется.
3. Слева откройте **SQL Editor** → **New query** → вставьте содержимое файла `supabase/schema.sql` из этого проекта → **Run**.
   Это создаст таблицу `registry_rows` и включит realtime-синхронизацию.
4. Слева откройте **Project Settings → API**. Скопируйте оттуда:
   - **Project URL** (похоже на `https://xxxxx.supabase.co`)
   - **anon public** ключ (длинная строка)

## Шаг 2. Настроить проект локально

1. Установите Node.js (18+), если ещё нет: nodejs.org.
2. В папке проекта:
   ```
   npm install
   cp .env.example .env
   ```
3. Откройте `.env` и вставьте туда значения из Шага 1:
   ```
   VITE_SUPABASE_URL=https://xxxxx.supabase.co
   VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
   ```
4. Проверьте, что всё работает:
   ```
   npm run dev
   ```
   Откройте адрес из терминала (обычно `http://localhost:5173`) — реестр должен загрузиться и один раз сам заполнится вашими 81 строкой из исходного файла (это происходит один раз, при первом запуске с пустой базой).

## Шаг 3. Выложить на Vercel (бесплатно, публичная ссылка)

Самый простой способ — без консоли, через сайт:

1. Залейте эту папку в GitHub (создайте новый репозиторий, например `plutosoil-registry`, и загрузите в него все файлы).
2. Зайдите на **vercel.com** → Sign up (можно через GitHub) → **Add New → Project** → выберите ваш репозиторий.
3. Vercel сам определит, что это Vite-проект. Перед деплоем откройте **Environment Variables** и добавьте те же две переменные, что в `.env`:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
4. Нажмите **Deploy**. Через минуту получите ссылку вида `plutosoil-registry.vercel.app` — её и рассылаете менеджерам.

(Альтернатива без GitHub: установить `npm i -g vercel`, затем в папке проекта выполнить `vercel` и следовать подсказкам — тоже спросит про переменные окружения.)

## Как это работает

- Таблица `registry_rows` в Supabase — это и есть общий реестр. Каждая строка — один менеджер видит правки другого **мгновенно**, без обновления страницы (через Supabase Realtime).
- Вверху справа видно, кто ещё сейчас открыл реестр (Supabase Presence).
- Кнопка **Excel** выгружает текущий (в том числе отфильтрованный) вид в .xlsx с двумя листами — как в исходном файле.
- Плотности для перевода в тонны (АИ-92 — 0,745, АИ-95 — 0,750, ДТ К5 — 0,840 кг/л) взяты из примечания исходного реестра.

## Важно про доступ

Сейчас таблица открыта на чтение/запись для всех, у кого есть ссылка на сайт и ключ `anon` (он зашит в код сайта — это нормально для Supabase, сам по себе он не даёт доступа ни к чему за пределами этой таблицы). То есть **любой, кто знает адрес сайта, может редактировать реестр** — входа по паролю нет.

Если нужно ограничить доступ (например, вход по email/паролю для ваших менеджеров) — это отдельная, тоже несложная настройка через Supabase Auth, скажите, если понадобится, сделаем.

```
plutosoil-registry/
├── supabase/schema.sql   ← выполнить в Supabase SQL Editor (Шаг 1)

│   ├── supabaseClient.js  ← подключение к Supabase (берёт ключи из .env)
│   ├── seedData.js        ← ваши 81 строка из исходного файла (для первого запуска)
│   └── main.jsx
├── .env.example            ← скопировать в .env и заполнить
└── package.json
```
